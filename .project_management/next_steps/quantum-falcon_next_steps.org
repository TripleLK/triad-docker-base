* Immediate Priorities

** CRITICAL: Implement Step 6.5 - Multiple Sources Extension Support
The next model must address the critical architectural gap where the Chrome extension only supports single source per field while the backend fully supports multiple sources.

*** Why This Is Critical
- **Data Integrity Risk**: Extension may overwrite existing sources
- **User Experience**: Confusing inconsistency between admin and extension
- **Step 7 Dependency**: Sub-model system requires multiple sources capability
- **Technical Debt**: Extension assumes single source throughout codebase

*** Success Criteria
- Extension displays all sources for each field
- Users can add/edit/delete/reorder sources
- Source type selection works (xpath, text, special, sub-model)
- API properly handles multiple sources without data loss
- Source activation/deactivation functional

* Technical Considerations

** Data Structure Changes
The extension currently expects single source per field:
```javascript
// Current assumption
field.xpath_selector = "//some/xpath"

// Needs to handle
field.sources = [
  {id: 1, type: 'xpath', selector: '//xpath1', order: 1, active: true},
  {id: 2, type: 'text', content: 'fallback', order: 2, active: true}
]
```

** UI Integration Points
- **Field Selection Panel**: Show source count and primary source
- **Field Detail View**: Expandable source list with management controls
- **XPath Selection Mode**: Choose which source to edit when selecting elements
- **Save Operations**: Batch save all source changes

** API Integration
- **Load Sources**: GET /api/xpath/fields/{id}/sources/
- **Create Source**: POST /api/xpath/fields/{id}/sources/
- **Update Source**: PUT /api/xpath/sources/{id}/
- **Delete Source**: DELETE /api/xpath/sources/{id}/
- **Reorder Sources**: PUT /api/xpath/fields/{id}/sources/reorder/
