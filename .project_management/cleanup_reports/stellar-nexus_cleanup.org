* Summary
Investigated and identified the root cause of AWS Bedrock batch inference failures. All 107 records consistently failed across multiple model attempts with the same underlying issue: the batch inference API is incorrectly parsing model IDs, extracting only the model name portion instead of using the full foundation model ARN.

** Major Accomplishments
- Fixed the create_batch_inference_job function to properly handle model IDs
- Tested multiple Claude models (3.7 Sonnet, 3.5 Sonnet, 3 Haiku)
- Identified that the issue is systemic across all Anthropic models
- Confirmed that prompt ARN and variables are being processed correctly
- Established that the problem is with AWS API model ID parsing, not our implementation

** Key Discovery
The batch inference API consistently transforms foundation model IDs like `anthropic.claude-3-haiku-20240307-v1:0` into just `claude-3-haiku-20240307`, which it then rejects as unsupported.

* Files Modified

** apps/content_extractor/aws_utils.py

- Removed incorrect logic that used prompt ARN as model ID
- Clarified documentation about model ID requirements

* Rationale
The investigation revealed that:
1. Input data format (promptArn + promptVariables) is correct

* Issues Identified
** CRITICAL: AWS Bedrock Batch Inference Model ID Parsing Bug
- **Symptom**: All batch jobs fail with "model not supported on this API" errors
- **Root Cause**: API extracts model name from full ARN and rejects it
- **Models Affected**: All tested Anthropic models (Claude 3.7, 3.5, 3 Haiku)
- **Impact**: Batch inference completely non-functional for Anthropic models
