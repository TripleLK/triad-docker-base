* REASONING

** AWS Credential Simplification
- Original implementation tried to manually handle environment variables
- Boto3's default credential chain is more robust and handles AWS CLI config automatically
- Eliminated BotoCoreError by letting boto3 handle credential discovery

** Bucket Naming Strategy
- Changed from site-specific buckets (triad-batch-processing-airscience-com) 
- To generic bucket (triad-bedrock-batch-processing) with domain-based prefixes
- Enables cost-effective multi-site processing in single bucket
- Structure: batch-processing/{domain}/files

** Format Optimization
- User confirmed only batch file needed for Bedrock batch inference
- Changed default from 'both' to 'batch' to eliminate unnecessary individual files
- Reduces S3 storage costs and simplifies batch inference workflow

* ARCHITECTURE

** S3 Structure
```

│   └── ...
```

** Bedrock JSONL Format
Each line in batch file:
```json
{
  "recordId": "domain_batch_timestamp_record_N",
  "modelInput": {
    "promptArn": "arn:aws:bedrock:us-east-1:891377295311:prompt/H52151JSYK",
    "promptVariables": {
      "content": "{...json_data_as_string...}"
    }
  }
}
```

** Data Flow
1. Query existing AIJSONRecord objects from database
2. Export to temporary JSON files
3. Convert to Bedrock JSONL format
4. Upload to S3 with organized structure
5. Clean up temporary files
6. Report success metrics

* ISSUES RESOLVED

** BotoCoreError Fix
- Problem: "BotoCoreError.__init__() takes 1 positional argument but 2 were given"
- Root Cause: Invalid AWS credentials causing boto3 internal errors
- Solution: Updated AWS credentials + simplified credential chain usage

** Upload Result Format Mismatch
- Problem: Django command expected dict results, aws_utils returned strings
- Solution: Updated upload_files_batch to return {success, s3_url, error} format

** Function Signature Mismatch
- Problem: delete_local_files called with wrong number of arguments
- Solution: Updated call to provide both file_paths and success_uploads parameters
