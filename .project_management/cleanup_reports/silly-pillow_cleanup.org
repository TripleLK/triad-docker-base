* Reasoning
The fixes addressed two critical UX pain points:

1. **Overly Strict Validation**: The original implementation required XPath input even for "Static Text" and "Special Function" source types, creating confusion and blocking legitimate use cases.

2. **Poor Related Object Creation UX**: Users had to manually select parent relationships when creating child objects, leading to extra clicks and potential errors.

The solutions maintain all existing validation logic while improving the user experience:
- **Conditional validation** now works at the model level through the `clean()` method
- **Pre-filled relationships** automatically detect URL parameters and pre-select appropriate parents
- **Backward compatibility** preserved - no breaking changes to existing functionality
