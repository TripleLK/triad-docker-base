* Architecture Discovery & Documentation Enhancement

** Critical Design Flaw Identified
The two-mode export → batch processing → import pipeline has a fundamental flaw:

### Working Two-Mode Structure:
```
ai_json_exports/two_mode/
├── Equipment_overall_details_domain_timestamp.json    # Contains _processing_mode: "OVERALL_DETAILS"
├── Equipment_models_batch_1_of_3_domain_timestamp.json # Contains _processing_mode: "MODEL_SUBSET"
├── Equipment_models_batch_2_of_3_domain_timestamp.json # Contains target_model_names: [...]
└── Equipment_models_batch_3_of_3_domain_timestamp.json # Contains _batch_info: {...}
```

### Broken Batch Output Structure:
```
batch_output/json_files/
├── record_1_timestamp.json    # NO metadata, just AI output
├── record_2_timestamp.json    # NO processing mode indicators
├── record_3_timestamp.json    # NO file relationship information
└── record_N_timestamp.json    # Generic naming, lost grouping context
```

** Root Cause Analysis
1. **Export Stage**: ✅ Creates proper two-mode files with metadata
2. **Batch Input**: ❓ Metadata may be included in input JSONs
3. **AI Processing**: ❌ AWS Bedrock AI doesn't preserve `_processing_mode` metadata in outputs
4. **Conversion**: ❌ Simple JSONL→JSON conversion loses all relationship context
5. **Import**: ❌ Cannot group files without metadata, defaults to single equipment per file
