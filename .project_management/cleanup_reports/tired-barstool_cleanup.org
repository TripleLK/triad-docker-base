* Architecture Issues Discovered

** Critical Problems Identified Through User Testing

1. **XPath Visual Selection Broken**
   - XPath selector saving doesn't work for sub-model sources
   - Broken for both initial creation and editing workflows
   - Context handling between parent and sub-field selection modes problematic

2. **Sub-Model Creation Workflow Missing**
   - No UI path to create new local_submodel sources
   - Can edit existing ones but cannot create new ones
   - Source type selection doesn't include sub-model options in creation flow

3. **Architectural Mismatch**
   - Current sub_fields array approach creates UI complexity
   - Doesn't match existing hierarchical menu patterns
   - Creates duplicate field management logic

** Fundamental Design Issues

The separate sub_fields approach creates several problems:
- Duplicate field management interfaces
- Complex context switching in XPath selector
- No natural way to create nested structures
- Doesn't leverage existing field hierarchy patterns

* Recommended Architecture Change

** Unified Field Hierarchy Approach
Instead of separate sub_fields arrays, implement parent-child field relationships:

```sql
ALTER TABLE xpath_content_extraction_fieldconfiguration 
ADD COLUMN parent_field_id INTEGER REFERENCES xpath_content_extraction_fieldconfiguration(id);
```

** Benefits of This Approach
1. **Unified Interface**: Same field management UI for all levels
2. **Recursive Structure**: Natural nesting support (sub-sub-fields, etc.)
3. **Consistent Patterns**: Leverage existing hierarchical menu system
4. **Simplified Logic**: One field management codebase instead of two

** Implementation Strategy
1. **Database Schema**: Add parent_field_id to FieldConfiguration
2. **API Updates**: Modify field endpoints to handle parent relationships  
3. **UI Unification**: Extend existing field menu to show hierarchy
4. **Parent Selector**: Move to field level instead of source level
5. **Field Creation**: Add field type popup for creating nested fields
